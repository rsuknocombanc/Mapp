# Bitácora Mapp
## 2026-11-16 — Inicio del proyecto
Se acuerda GitHub como fuente de verdad, Mapp para Safari iPhone, mapas personalizables y GitHub Pages con Actions. La metodología exige aprobación de diseño antes de implementar.
## 2026-11-16 — Diseño visual
Se toma como inspiración mapa vintage topográfico de aventura estilo Firewatch, con colores oliva, papel antiguo, curvas de nivel, bosques y estética ilustrada. El usuario aprueba explorar distintas versiones visuales, incluyendo vista estrictamente vertical y manchas verdes con textura.
## 2026-11-16 — Prototipo inicial
Se solicita un prototipo interactivo con marcador de Jimny visto desde arriba. Se genera HTML v0.1, pero el visor interno de ChatGPT mostró cartografía en carga. El usuario autoriza subir el trabajo y configurar publicación GitHub Pages. Se crea el repositorio oficial rsuknocombanc/Mapp y rama feature/bootstrap-vintage-map.
## 2026-11-16 — Renderizado artístico v0.3 (MAP-0002)
Aprobación explícita de implementar una pasada visual artística; objetivo: mapa de aventura retro, vista estrictamente vertical. Se utiliza la misma rama temporal feature/bootstrap-vintage-map y el PR #1, evitando proliferación de ramas.
Implementado: paleta de atlas, UI más discreta, 3 patrones de bosque generados en Canvas y aplicados a polígonos vectoriales georreferenciados mediante MapLibre fill-pattern; sombreado suave con DEM externo Mapterhorn, opcional; control de carga con mensaje de fallo. Mantiene GPS y marcador del Jimny.
Comprobaciones locales: sintaxis JavaScript con node --check; interfaz simulada en Chromium con MapLibre sustituido por mock, selección de estilo, texturas y relieve registrados sin errores JS. Estas pruebas NO equivalen a cartografía real cargada ni Safari iPhone aprobado.
Pendientes: comprobar datos y cobertura del proveedor de elevación, funcionamiento de tiles en Safari real, contraste y usabilidad, revisión/aprobación visual, merge de PR #1; Pages de prueba en gh-pages sujeto a verificar URL.

Bandas provisionales: 650/1150/1900/3200 m. Nuevo requerimiento MAP-0003 y ADR-0003; ADR-0002 conservado históricamente. CI ampliado con validación de JS y contrato UI; pruebas mock de Chromium locales (no Safari real). Geocodificador público sin SLA, usar prudentemente.
Próxima acción: verificar Actions CI y Pages de este commit, evaluar mapa real y búsqueda en Safari; recoger observaciones; no mergear a main sin autorización.

## 2026-11-17 — v0.5 Árboles ilustrados (MAP-0007)
Se aprueba la maqueta con árboles sobre vegetación (estética pictórica, masas de pinos verde oscuro); el usuario indica «avancemos», autorizando la implementación. Se incorpora un módulo independiente `assets/forest.js` con 8 variantes originales de coníferas/tríos dibujadas en Canvas, registro como sprites MapLibre y posiciones deterministas por rejilla Mercator sobre polígonos OpenFreeMap `landcover`, con densidad ilustrativa minoritaria en parques/praderas. Sin patrones repetitivos y sin DEM.
Las posiciones se conservan al desplazar dentro de un bucket entero de zoom; la distribución cambia en transiciones de nivel por presupuesto de detalle. Hasta 130 árboles móviles y 260 escritorio; generación acotada a la vista y diferida tras movimiento/carga, con fallback seguro.
Las capas de árboles se insertan debajo de las vías y ruta y no alteran búsquedas ni GPS. Pruebas locales: Python contrato, Node sintaxis, Haversine y lógica forestal (geometría, huecos, semillas y límites), Chromium móvil con MapLibre/Photon/OSRM simulados. **No** hay UAT real con tiles ni Safari/Edge. Nueva documentación MAP-0007, ADR-0007 y UAT-MAP-0007; issue #4 de diseño permanece abierto hasta validación.

## 2026-11-17 — v0.5.1 MAP-0008, observabilidad para diagnóstico visual
El usuario observó que casi no hay árboles ni diferencia visual clara entre estilos en captura de Edge. Se confirma brecha frente a maqueta (UAT MAP-0007 NO superada). El algoritmo de generación trabaja sobre clases OSM específicas y una rejilla de gran separación; los tests simulados usaban polígonos artificiales, por lo que no prueban suficiencia de densidad real. Tinta es el estilo de menor contraste en la captura. No se concluye aún una causa única sin datos de teselas de producción.
El usuario solicita explícitamente versión arriba a la derecha para futuras capturas. Se agrega una etiqueta v0.5.1 con estilo, zoom y conteo de pinos generados mediante callback local del módulo forestal; no solicita GPS ni remite telemetría. Cambios limitados a la interfaz/observabilidad, sin ajustar todavía distribución, tamaño, vegetación ni paleta. Tests locales contrato, sintaxis Node, matemáticas de ruta, geometría de bosque y Chromium simulado: OK. UAT real pendiente.

## 2026-11-17 — Mapp v0.6.0: árboles de acuarela originales y arte único (MAP-0009)
El usuario validó una lámina de ocho pinos originales de acuarela y solicitó implementarlos. Se confirma que Acuarela, Bosque y Tinta son **materiales de un solo estilo**, no tres temas. Se mantiene la rama temporal `feature/bootstrap-vintage-map`, PR #1 y main sin cambios.
Se sustituyó la iconografía sintética de v0.5 por 8 dibujos transparentes originales; 3 variaciones leves de pigmento por dibujo dan 24 sprites en un único atlas PNG de 294 KB. La posición se ancla a la geografía con una rejilla Mercator de ~32 px (antes 72 px), clasificación de landcover/landuse/park, huecos geográficos y densidad mayor en wood que en praderas o reservas; presupuesto 270 móvil y 480 escritorio, selección imparcial en grandes ventanas.
Paleta única: papel #EFDEB9, bosque #6B8652, agua petróleo #265D65, caminos #9B5737; se elimina el selector de temas y se conserva panel de arte (Acuarela · Bosque · Tinta) como una definición. Buscador, GPS, rutas automáticas OSRM y trazado libre sin modificaciones funcionales; versión y contador siguen visibles arriba derecha.
Pruebas locales exitosas: node --check, contrato UI, pruebas geométricas/presupuestos y rutas, Chromium simulado con **decodificación real del atlas PNG** y MapLibre/OSRM/Photon simulados. **Sin UAT visual en Edge y Safari con teselas reales**, ni cifras de rendimiento. No fusionar main antes de la validación del usuario.

## 2026-11-17 — Corrección autorizada v0.6.1 / MAP-0010
El usuario suministró `mapp_diagnostico_render.json`: en v0.6.0, `sourceExists=true`, `spriteExists=true`, `layerExists=false`, 22 pinos generados y 8 dentro de la vista en muestra de diagnóstico. Con el error de MapLibre de Edge se determinó causalidad: `zoom` aparecía dentro del producto de `icon-size` en vez de usarse como entrada de un `interpolate` de nivel superior. El motor rechazaba el `addLayer`, pero los tests mock lo permitían, por eso CI era verde sin render real.
Usuario aprobó expresamente corregir y publicar v0.6.1. Solución: helper `treeIconSizeExpression()` hace interpolación por zoom top-level con multiplicación de escala por parada, conserva variación de tamaño; después del `addLayer` se comprueba que realmente exista. Se añade test contra `@maplibre/maplibre-gl-style-spec@26.4.4` con control negativo de la expresión antigua, más mock que exige top-level; documentación MAP-0010, ADR-0010 y UAT.
Pruebas CI y Pages se verificarán por SHA; no afirmar validación real Safari hasta UAT. Main se mantiene estable y el PR #1 abierto.
